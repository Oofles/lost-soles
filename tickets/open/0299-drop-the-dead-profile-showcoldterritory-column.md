## Description

`Profile.showColdTerritory` (`amplify/data/resource.ts`) is a preference column from `02` T1 that
nothing reads or writes. `0100` shipped the cold wash as part of atlas itself: the palette's
`coldWash` is 1 in atlas and 0 in adventure (`lib/fog/fog-uniforms.ts`), with no switch, and it left
the column unwired on purpose. D-133 says atlas renders cold ground, full stop, and D-395 settles
that there is no toggle. Drop the column, the same way `0296` dropped `mapMode`.

Filed by capability 15's audit as its one code-was-wrong divergence (D-262).

## Acceptance criteria

- [x] `showColdTerritory` is gone from the `Profile` model and its doc comment in
      `amplify/data/resource.ts`, and from the `it.each` grant list in
      `amplify/profile-model.test.ts`.
- [x] `02-data-model.md`'s T1 `Profile` row no longer lists `showColdTerritory`, and cites D-395.
- [x] After deploy, the AppSync introspection's `type Profile` has no `showColdTerritory`.

## Notes

Removing a nullable AppSync/DynamoDB attribute is non-destructive: existing items keep a stray
attribute that nobody reads. Do not backfill or scrub. `0296`'s Resolution has the exact shape:
three files, plus a post-deploy `aws appsync get-introspection-schema --api-id
nog4xy2l7baqlhghpndh2565qe --format SDL`. The audit already amended 02 T1's summary row and its S-5
line (D-395); this ticket owns only the T1 attribute row, which goes with the column.

## Resolution

Same shape as `0296`, three files plus the docs index:

- `amplify/data/resource.ts`: removed `showColdTerritory: a.boolean()` and its
  `/** Atlas-only overlay (D-133). */` comment from the `Profile` model.
- `amplify/profile-model.test.ts`: dropped `"showColdTerritory"` from the `it.each` list of fields
  that carry no rule of their own. The suite passes (9/9).
- `docs/02-data-model.md`: deleted the T1 attribute row. Under the table I added a line saying
  there is no `showColdTerritory` attribute because atlas always paints cold ground (D-133, D-395),
  next to the existing `mapMode` line from `0296`. I also changed the T1 summary row's note from
  "goes in `0299`" to "dropped by `0299`". That is a tense change only; the audit wrote the rest of
  that row.
- `docs/INDEX.md` was regenerated by `build-index.mjs`.

There was no backfill or scrub. Existing DynamoDB `Profile` items keep a stray attribute that
nothing reads, which the ticket's Notes say is fine. No new decision: D-395 already covers this.

Gates: typecheck clean and `tickets.mjs validate` reports 0 errors. Every `node scripts/…` guard in
`amplify.yml` passed on a clean copy, except two that cannot run there. `check-d123-trigger-b` needs
`.git`, so I ran it in the real repo, where it passed ("Trigger B has not fired").
